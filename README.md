# 做题小助手

基于 [HanakoAI](https://github.com/zyf2007/HanakoAI) 改良的 Android 悬浮窗 AI 搜题工具，由 [lxy005tt-collab](https://github.com/lxy005tt-collab) 独立维护。感谢原作者与上游贡献者。

[项目主页](https://github.com/lxy005tt-collab/ZuotiAssistant) · [问题反馈](https://github.com/lxy005tt-collab/ZuotiAssistant/issues) · [发行页面](https://github.com/lxy005tt-collab/ZuotiAssistant/releases) · [来源说明](NOTICE.md) · [AGPL-3.0](LICENSE)

左球打开快捷菜单，右球截取整屏并交给 AI。答案在同一个悬浮窗口里逐字显示，复制、重试和追问也都可以在小窗中完成。

当前版本为 `1.0.3`：[下载完整版（推荐）](https://github.com/lxy005tt-collab/ZuotiAssistant/releases/download/v1.0.3/ZuotiAssistant-1.0.3-full-arm64-v8a.apk) · [全部安装包与更新说明](https://github.com/lxy005tt-collab/ZuotiAssistant/releases/tag/v1.0.3)。本项目不是 HanakoAI 官方发行版。

## 相比原版的主要改良

- **一体式双球悬浮窗**：入口、菜单和答案共用一个窗口，支持拖动；点击外部空白处可收起。
- **整屏截图直送 AI**：右球一键截图并发送，不再要求框选区域；等待时向右展开并显示单色流光，不显示截图或思考文字提示。
- **连续截图对话**：每次启动悬浮窗开始新对话，右球截图、区域截图和文字追问都延续本次上下文；左球「新题」可随时重新开始。
- **区域截图**：左球菜单中的「区域」打开整屏预览，拖动框选后确认，只把选中区域交给 AI；取消不发起请求。
- **精简答案气泡**：第一段答案到来后淡入白底黑字气泡，无圆角外投影，随文字增长至高度上限后滚动；输出结束后，复制、重试、追问三个图标在紧凑底栏中渐显。
- **模型思考强度**：可选自动、低、中、高等档位，实际可用选项取决于模型和接口。
- **两种截图方案**：主页直接切换系统录屏或 Shizuku，问号按钮说明各自优缺点。
- **隐匿模式**：主页「截屏方案」下方开关，尝试让系统截图、录屏和投屏排除本应用悬浮窗；屏幕上的浮窗照常显示。仅透明隐藏，失败提示不支持。
- **可调悬浮窗**：尺寸默认 75%，支持调整尺寸、背景透明度、答案字号、逐字显示和空白处收起。
- **黑白极简界面**：首页与设置页共用固定顶部栏、圆角分组卡片与黑白灰配色；顶部与桌面使用同一只 SVG 低多边形猫，支持深浅模式。
- **精简服务接入**：移除 Kirari Network 的登录、额度和专属网关，使用自行配置的模型 API；兼容旧设置及历史记录。
- **图标与稳定性调整**：更新应用及悬浮窗图标，修复展开闪退、标签裁切，调整气泡收起动画。

## 快速开始

新用户优先选择 `full-arm64-v8a` 安装包（Android 7.0 及以上）。`lite` 不含本地 OCR，`armeabi-v7a` 用于支持 32 位应用的旧设备。

已安装旧测试版或之前 `dev-upgrade` 包的用户，继续使用[兼容升级包](https://github.com/lxy005tt-collab/ZuotiAssistant/releases/download/v1.0.3/ZuotiAssistant-1.0.3-full-dev-upgrade-arm64-v8a.apk)，可保留原包名、签名、配置和历史记录。1.0.1 起显示名称统一为「做题小助手」，升级通道不变。该兼容包启用与正式版相同的代码优化，但沿用旧测试证书；新用户使用普通正式包。请勿先卸载旧应用。

1. 安装应用，在「设置 → 模型提供方」填写 API 地址、API Key 和接口类型。
2. 在「模型设置」中选择多模态模型。默认模式会发送截图，因此所选模型必须支持图像输入；也可改用 OCR 模式。
3. 在主页选择截图方案，打开悬浮窗权限，再启动悬浮球。
4. 切换到需要阅读的题目页面，点击右球开始截图解题。
5. 答案输出结束后，可复制、重试、追问或再次截图。后续截图会带上本次对话前文；需要独立解题时，先点左球菜单「新题」。

收起气泡会保留当前答案和正在生成的任务。首次模型配置与系统授权仍需在主界面完成。

### 左球快捷菜单

| 入口 | 用途 |
| --- | --- |
| 答案 | 展开当前答案 |
| 新题 | 结束当前上下文，下一次截图开始新对话；旧对话保留在历史记录 |
| 区域 | 在截图预览中框选范围，确认后解题 |
| 联网 | 开启或关闭联网搜索 |
| 退出 | 关闭悬浮窗并停止当前截图会话 |

多模态与 OCR 在主页切换。悬浮窗靠近屏幕边缘展开后，收起会停在当前控制按钮的位置，不再强制返回展开前的坐标。

### 两种处理模式

| 模式 | 处理方式 | 适用场景 |
| --- | --- | --- |
| 多模态视觉（默认） | 直接把截图发送给支持视觉的模型 | 图表、几何图、公式与混合内容 |
| OCR | 先识别文字，再交给文本模型 | 以文字为主的题目 |

Full 版本内置 ML Kit 中文 OCR；Lite 版本不包含本地 OCR，可配置云端 OCR。

## 截图方案

| 方案 | 优点 | 使用条件与限制 |
| --- | --- | --- |
| 系统录屏 | 无需安装额外工具，按系统提示授权即可 | 新的录屏会话需要确认，使用时会有屏幕共享提示 |
| Shizuku | 按需截取单张图片，无需启动系统录屏会话 | 需安装、启动并授权 Shizuku；通过调试启动后，手机重启需重新启动服务 |

两种方案都可能无法截取受保护的页面，Shizuku 不保证避开应用检测。切换方案会停止当前悬浮窗，需要重新启动。

截图会发送至你配置的模型服务；启用联网搜索后，模型可能将搜索词交给配置的搜索服务。

正常解题的截图会保存在应用私有目录的 `history_images` 中，可从「设置 → 历史记录 → 题目详情」查看，不会自动保存到系统相册。

### 连续截图与上下文

每次启动悬浮窗会从空白对话开始。首次截图创建历史记录，之后的整屏截图、区域截图和文字追问按顺序追加到同一段对话；收起、拖动或重新展开气泡不会清空上下文。退出悬浮窗后重新启动会开始新对话，也可以在左球菜单点「新题」手动重新开始。回到应用主页本身不会结束仍在运行的悬浮窗会话。

多模态会将原始截图、各轮补图和已完成的回答按消息顺序交给模型；OCR 模式会保留每轮识别文字。会话沿用首次截图的处理模式，切换处理模式后可以点「新题」开始。新截图可能是原题的补充，也可能是新问题，模型提示会要求以最新问题为准、避免混用不同题的条件。

重试只重新生成当前轮次，复用该轮图片和已识别文字，不会重复添加截图。截图失败不会清空前文；图片丢失时明确报错，不会悄悄省略。补充截图可在同一条历史记录中查看。联网开关继续作用于后续请求。

本版保留完整对话，不自动用摘要替换题图；长对话的请求用量会随上下文增加，并受所选模型的上下文限制。

Android 12 及以上会尝试在截图合成时排除本应用的悬浮窗图层，让屏幕上的悬浮窗和展开动画保持可见、截图中的题目保持完整。这依赖系统内部接口，兼容性因系统而异；接口不可用时会短暂隐藏悬浮窗，截取后再展开。此功能只处理本应用的悬浮窗。

### 隐匿模式

主页「截屏方案」下方可开关隐匿模式，设置会保存并即时生效。默认开启，沿用原先尝试排除悬浮图层的行为；覆盖入口小球、菜单、答案、追问和区域选择窗口。关闭后，系统截图或录屏可以包含悬浮窗，但本应用自己搜题截图时仍会单独避开它。重置悬浮窗外观不会改变这个开关。

该模式仅尝试透明隐藏，不设置 `FLAG_SECURE`、不添加黑块、不主动禁止整屏截图。Android 12 以下或接口调用失败时，主页显示「不支持透明隐匿」；运行中失败也会弹出提示。不同窗口的失败状态会合并显示，避免其中一个窗口失败却显示全部正常。

「已请求透明隐藏」只说明系统接受了调用，不能证明当前手机的截图、录屏或投屏已正确排除内容。**请分别用系统截图和录屏验证。** 系统键盘、状态栏、通知及其它应用窗口不在此功能的隐藏范围内。依据见 [Android 图层接口说明](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/android12-release/core/java/android/view/SurfaceControl.java)；实际兼容性以设备为准。

## 模型与功能

支持 OpenAI Compatible、OpenAI Responses、Anthropic 和 Google Gemini 接口。OCR、文本、多模态任务可分别指定提供方和模型。

新配置不预填模型。每种模型均可单独「留空」，重启后仍保持为空；升级保留已有有效选择。多模态解题与追问仅依赖多模态模型，OCR 路线才需要 OCR 与文本模型。

「设置 → 更多 → 答案字号」可调整 12–22 sp，同时作用于悬浮答案和历史详情的正文、公式与 HTML 内容。

- 支持流式答案、Markdown / LaTeX、历史记录、答案版本切换、片段引用和追问。
- 支持 Tavily、Brave Search、Serper 及 Tavily 兼容搜索接口。
- 支持手动输入模型名、收藏模型和连接测试。
- 思考强度默认「自动」，不额外附加思考参数；OCR 识字请求不受该设置影响。较高强度可能增加等待时间与用量。
- 档位根据模型、接口及已知托管服务映射；预算型模型显示 token 预设，仅有开关的模型显示开启/关闭，未识别型号沿用服务默认值。具体范围见 [思考强度适配](docs/reasoning-models.md)。
- 应用更新与下载入口指向本仓库；原项目链接仅用于来源说明。

## 本地构建

需要 JDK 17、Android SDK 36，以及项目自带的 Gradle Wrapper。Windows 建议使用纯英文路径（如 `D:\Projects\ZuotiAssistant`），避免 AIDL 工具处理路径时出错。

```bash
git clone https://github.com/lxy005tt-collab/ZuotiAssistant.git
cd ZuotiAssistant
./gradlew :app:assembleFullDebug
```

Windows 使用 `gradlew.bat`。Android SDK 路径可通过本机 `local.properties` 或环境变量配置，勿提交本机配置与密钥。

如需与已有不同签名的 Hanako 并存：

```bash
./gradlew :app:assembleFullDebug -PhanakoParallelDebug=true
```

该选项沿用旧构建参数名，生成「做题小助手 测试版」，应用 ID 为 `fun.kirari.hanako.dev`。默认包名保留为 `fun.kirari.hanako`，便于同签名版本覆盖升级并保留数据；独立仓库并不改变 Android 的签名规则。

运行检查：

```bash
./gradlew :app:testFullDebugUnitTest :kirari-llm-core:testDebugUnitTest
```

签名发布与 Full / Lite、arm64 / 32 位变体说明见 [发布流程](docs/release-process.md)。`kirari-llm-core` 是保留的通用模型协议模块名称，不包含 Kirari Network 专属服务接入。
